## 1. TỔNG HỢP CÁC QUYẾT ĐỊNH KIẾN TRÚC TRỌNG YẾU (DECISION LOG)

| Mã quyết định | Chủ đề kiến trúc | Lựa chọn được phê duyệt | Phương án thay thế đã bác bỏ | Lý do & Lợi ích kỹ thuật |
|---|---|---|---|---|
| **DEC-001** | **Kiến trúc Tổng thể** | Giữ vững **Modular Monolith** trong một Spring Boot application. | Phân tách Microservices phân tán. | Tránh độ trễ mạng, chi phí quản lý transaction 2PC/Saga phức tạp; bảo toàn khả năng khóa dòng ACID PostgreSQL của engine vé. |
| **DEC-002** | **Nguồn Sự Thật Tồn Kho** | **PostgreSQL 17 ACID** là Single Source of Truth duy nhất. | Dùng Redis lưu tồn kho ghế/GA. | PostgreSQL đã chứng minh xử lý hoàn hảo hàng trăm concurrent requests không oversell; Redis làm tăng nguy cơ lệch dữ liệu khi mạng gặp sự cố. |
| **DEC-003** | **Mô hình Phân Quyền** | **Four-Role RBAC** (`CUSTOMER`, `STAFF`, `ORGANIZER`, `ADMIN`) kết hợp **Event Scope**. | Role đơn trị trên bảng users hoặc Attribute-Based Access Control (ABAC) quá phức tạp. | Bảng quan hệ `roles` và `user_roles` cho phép 1 user giữ nhiều role; Event Scope ngăn chặn tuyệt đối truy cập chéo giữa các Organizer và Staff. |
| **DEC-004** | **Quản lý Phiên Đăng Nhập** | **Access Token JWT (15m)** + **Refresh Token (7d)** lưu trong **HttpOnly, Secure Cookie** với **Token Family Rotation**. | Lưu JWT vĩnh viễn trong `localStorage` hoặc Session Stateful trên Server. | Loại bỏ hoàn toàn rủi ro bị mã độc XSS đánh cắp Refresh Token; Token Family phát hiện và vô hiệu hóa ngay lập tức token bị rò rỉ. |
| **DEC-005** | **Đăng Nhập Google OIDC** | **Authorization Code Flow với PKCE** qua backend Spring Security OAuth2 Client. | Implicit Flow hoặc Frontend GIS verify token trực tiếp. | Giữ an toàn tuyệt đối Google Client Secret; kiểm tra nghiêm ngặt `sub`, `iss`, `aud`, `state`, `nonce` trên server-side. |
| **DEC-006** | **Chính sách Gộp Tài Khoản Google** | **Explicit Account Linking** (Yêu cầu nhập mật khẩu xác nhận). | Tự động gộp tài khoản ngầm định (Silent Auto-Merge theo email). | Ngăn chặn triệt để tấn công chiếm quyền tài khoản (Account Takeover) khi kẻ xấu tạo email giả trên IdP bên ngoài. |
| **DEC-007** | **Cổng Thanh Toán Ngoài** | Kiến trúc **Ports and Adapters** (`PaymentGatewayPort`), đề xuất **VNPAY Sandbox** làm cổng đầu tiên; duy trì **Payment Simulator**. | Nhúng trực tiếp SDK VNPAY vào domain service; xóa simulator. | Độc lập nhà cung cấp; simulator tiếp tục bảo vệ bộ test tự động CI/CD chạy độc lập không phụ thuộc Internet. |
| **DEC-008** | **Xác Nhận Đơn Hàng Thanh Toán** | Chỉ xác nhận khi nhận **Server-to-Server IPN Webhook** có chữ ký số hợp lệ; **Return URL chỉ hiển thị**. | Cho phép Return URL gọi API xác nhận đơn hàng. | Người dùng có thể sửa đổi query params trên trình duyệt để gian lận thanh toán; chỉ Webhook IPN mới là nguồn sự thật. |
| **DEC-009** | **Trọng Tài Thanh Toán Muộn** | Đơn hàng `EXPIRED` thanh toán muộn chuyển sang **`REFUND_REQUIRED`**, tuyệt đối không cấp vé. | Cố gắng cấp vé mới hoặc ép nhả vé của người khác. | Bảo vệ tính toàn vẹn tồn kho; chỗ đã nhả có thể đã được người khác mua; hoàn tiền là giải pháp công bằng và minh bạch. |
| **DEC-010** | **Kiểm Soát Soát Vé (Check-in)** | Khóa dòng **`UNIQUE(ticket_id)`** trong bảng `ticket_check_ins`. | Dùng Redis flag hoặc biến cờ in-memory. | Cơ chế duy nhất bảo đảm chống quét trùng lặp vé (Anti Double Check-in) 100% trong môi trường phân tán nhiều cổng soát vé. |
